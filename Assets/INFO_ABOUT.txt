END-TO-END DEEP RL

- Map raw camera images directly to control actions without intermediate feature extraction or perception modules.
- Neural network processes pixel data from the camera node as the agent's observation, outputting velocity commands for obstacle avoidance.

What It Is
- Train a single DNN (typically CNN-based) taking high dimensional inputs like raw RGB or grayscale image and outputs discrete or continuous choices.
- The network learns entire pipeline - perception, decision-making, and control through trial-and-error interactions guided by reward function.

When To Use
- Tasks needing tight perception-action coupling (dynamic obstacle avoidance)
- Latency (<100ms)

How It Works
- Observation: ROS2 node subscribes to camera, stacks 3-4 consecutive frames for motion, normalized to, feeds to CNN backbone (e.g., NatureCNN from Stable baselines3)
- Policy Training: Algorithms like PPO or DQN optimize via actor-critic or Q-value estimation; PPO handles continuous actions better for smooth navigation.
- Reward Design: Sparse (goal reach) or dense (distance to nearest obstacle via raycasts in sim); no manual labels needed beyond shaping.
- ROS2 Integration: Custom Gym env wraps ROS2 lifecycle node—reset spawns robot, step publishes actions to /cmd_vel, collects images via cv_bridge.

Why Choose It
- Eliminates hard-engineered pipelines - better generalization via learned representations
- Rewards focus on outcomes and not heuristics

How It Works
- Observation: ROS2 node subscribes to /camera/image_raw, stacks 3-4 consecutive frames for motion, normalizes to, feeds to CNN backbone (e.g., NatureCNN from Stable Baselines3).
- Policy Training: Algorithms like PPO or DQN optimize via actor-critic or Q-value estimation; PPO handles continuous actions better for smooth navigation.
- Reward Design: Sparse (goal reach) or dense (distance to nearest obstacle via raycasts in sim); no manual labels needed beyond shaping.
- ROS2 Integration: Custom Gym env wraps ROS2 lifecycle node—reset spawns robot, step publishes actions to /cmd_vel, collects images via cv_bridge.

Advantages
- Eliminates hand-engineered pipelines
- Enables generalization to unseen obstacles via learned representations
- Reward focus on outcomes, not heuristics suiting vision-only setup where depth sensors are absent
- Single model reduces hyperparameters and debugging, scales with data
- Learning robust policies and partial occlusions or textures without explicit rules
- Modern methods like PPO converge in 1-10M steps in sim, transferable to ROS2 hardware

Disadvantages
- Data Hunger
- Vision inputs explode state space (10^6 dims vs lidar's 360), black box opacity hinders debugging
- Domain randomization (lighting, textures) needed but imperfect

Does It Work
- Works reliably in controlled settings - e.g., DQN navigates from pixels (Atari benchmark), PPO avoids obstacles in Gazebo/ROS2.
- Failures stem from poor rewards, overfitting to sim visuals, mitigated by curriculum learning, and diverse training data.
- In ROS2 vision-only robots, it succeeds for indoor navigation but struggles in sparse-reward outdoor clutter without auxiliary shaping.
